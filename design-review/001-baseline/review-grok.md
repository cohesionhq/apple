The core set is a system-styled SwiftUI app with a few branded moments. The tab bar, article, and status colors are doing real design work. The iPad shell, task surfaces, and color rules are not.

## What works

- The needs-you / done / failed line (hand, check, cross, plus a short label) is clear on the dashboard and worth using everywhere a status appears.
- The floating glass tab bar, the badge on Intelligence, and the circular back / capsule toolbar buttons are the right iOS 27 chrome.
- The article reader has a real title, byline, source, and body scale. It is the screen to measure the others against.
- Agent discs in distinct colors are the one personality trait that already reads as Cohesion, especially Atlas in the chat header and the user bubble in indigo.
- Settings separates Server, This iPhone, and Unpair into the right groups, and the chat poll (A / B / C with a single check) is the right kind of custom control.

## To reach 9+

1. **One shell.** Same large-title grammar, same settings entry, tab bar hidden once a screen has a back button or a composer, and a bottom inset so the last row always clears the glass. This is the consistency and spacing floor.
2. **An iPad that is a different layout, built from the same rows.** Fixed sidebar footer, sections including Agents, a 680pt reading column for the dashboard and chat, and real columns for tasks. Do this before any more visual polish; the wide shots are the lowest scores.
3. **One meaning per color.** Status orange, green, and red only on status. Agent color only on discs. Everything else neutral. Retint settings, size pills, and flags in the same pass.
4. **Object headers instead of menus.** A task opens on its name, status, and due date. An agent opens on its disc, name, and role. A contact opens on an initial, name, and role. Property rows come after, in `.body` / `.subheadline.secondary`.
5. **Design the two working surfaces.** The actor permission is one bottom card with a single primary action and code that fits. The chat answer is `.body`, cues and tool lines are `.footnote.secondary`, and tables reflow under 390pt. Those two screens are the product; the lists can stay quiet once they share a row.
